# FabricSandbox 实测基准 2026年11月1日

这些数字衡量本机 CPU 上的静态网络模型计算时间。未启动 GPU、真实网络、HTTP 服务、数据库或多进程，不代表真实训练吞吐和分布式加速。

## 测量条件

- Python 3.12.14，macOS 26.6.2，arm64。环境限制未获取 CPU 型号，避免跨机性能比较。
- `time.perf_counter()`，每个阶段先预热 1 次，再重复 5 次，保存全部原始样本。表格为中位数 [最小值, 最大值]，单位 ms。
- 各阶段独立计时，不包含反序列化、进程启动、UI、HTTP 和存储。固定输入的领域函数是纯内存计算。
- 拓扑扩展实验固定 8 个 spine、每节点 8 GPU、1 个请求 16 GPU 的 ring 作业、10 Gbps/流量单元和 rail-aware 策略。拓扑规模变化时调整 leaf 数和每 leaf 的节点数。
- 这是轻负载规模试验，不能由 1024 GPU 拓扑生成成功推断 1024 GPU 满负载训练可被准确或实时模拟。

1024 GPU 对应 16 leaf × 8 节点/leaf × 8 GPU/节点。8 个 spine 不参与 GPU 总数乘法。此组输入只有 1 条跨节点聚合流，各规模之间的路径跳数也可能变化，因此它是端到端模型成本观察，不是严格单变量复杂度证明。

## 通信模式与作业规模

固定默认 1024 GPU 拓扑，单作业请求数逐步增加。下列流数为模型内的无向节点对聚合流，不能当成 GPU rank 间消息数。

| 请求GPU数 | ring流数 | ring评估ms | all-to-all流数 | all-to-all评估ms |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 1 | 0.692 | 1 | 0.683 |
| 32 | 4 | 0.934 | 6 | 1.091 |
| 64 | 8 | 1.266 | 28 | 3.183 |
| 128 | 16 | 2.005 | 120 | 12.449 |

128 GPU 作业占 16 个节点。all-to-all 产生 16×15/2=120 条无向节点对流，ring 为16条。当前实现逐流寻找候选最短路径，通信密集度比仅拓扑 GPU 数更能解释评估成本。

## 策略对比与有效边界

使用 `rail-aware-comparison.json`，流量单元需求为 200 Gbps。

| 策略 | 大作业rail对齐率 | 大作业吞吐代理Gbps | 小作业吞吐代理Gbps |
| --- | ---: | ---: | ---: |
| first-fit | 50% | 100 | 不适用，全部在同一节点 |
| rail-aware | 100% | 100 | 133.333333 |

对齐率来自 GPU rail 标签匹配。当前网络图仅建模节点/leaf/spine，未建模独立 rail/NIC 物理通道。这组数据不能支持“rail-aware 提高真实吞吐”的结论，也不能将 first-fit 的 None 当作 0 Gbps。已有文档中的“0% 到 100%”不适用于这份实际夹具的大作业指标。

## 分片结果一致性

| 版本 | 1 worker | 2 workers | 3 workers | 2 workers中worker-1失效 |
| --- | --- | --- | --- | --- |
| 原版相对1worker结果 | 基准 | 不一致 | 不一致 | 一致 |
| 优化版相对1worker结果 | 基准 | 一致 | 一致 | 一致 |

原版2/3 worker各自从空负载选路，两个作业都走spine-0。合并后链路声称200 Gbps，但逐流相加为400 Gbps，超过200 Gbps容量。优化版先统一选路，并按全局链路竞争重算flow/job/link指标，以上场景均未出现容量违规或link-flow不一致。

这次优化优先保证计算一致性。优化版多执行一次全局求值，分片处理仍顺序运行，因此 CPU 开销可能增加。`recovery_ms` 覆盖完整同步计算过程，不能解释为真实故障检测或网络恢复时延。

## 复现

```bash
python scripts/benchmark_review.py --repeats 5 --output docs/benchmark_review.json
# 如果保留了原始目录，可同时验证修复前结果
python scripts/benchmark_review.py --repeats 5 --compare-root /path/to/original/gpu --output docs/benchmark_review.json
```

`benchmark_review.json` 保存原始样本、运行环境、关键代码SHA-256、worker分配和容量检查结果。重复测量允许时延波动，正确性不变量应保持。
